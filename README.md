# Дашборд регистраций участников

Одна страница, которая за минуту показывает, сколько людей зарегистрировалось на обучение в языковой школе, сколько оплатило и откуда они пришли.

## Что показывает

- **Три крупные цифры:** всего регистраций, оплатили, не оплатили (с процентом от всех).
- **Таблица по каналам** (Telegram, Instagram, Email-рассылка, Сайт, Партнёры): всего, оплатили, не оплатили, % оплаты.
- **Таблица по городам:** те же столбцы.
- В обеих таблицах строка «Итого», строки отсортированы по числу регистраций.

На текущих данных: **30 регистраций, 20 оплатили, 10 не оплатили**.

## Как открыть

Откройте [`public/index.html`](public/index.html) двойным кликом. Интернет и установка программ не нужны, всё работает в браузере.

## Как посмотреть новую выгрузку

1. Нажмите **«Загрузить другой CSV»** в правом верхнем углу.
2. Выберите файл. Страница пересчитает цифры и таблицы.

Файл обрабатывается только в вашем браузере и никуда не отправляется.

### Формат CSV

Первая строка — заголовок. Нужные столбцы: `city`, `source`, `paid`. Остальные (`name`, `registered`, `ticket`) допустимы, но для расчёта не требуются.

```csv
name,city,registered,source,ticket,paid
Айгерим,Астана,2026-10-30,Telegram,VIP,да
Алина,Астана,2026-11-08,Telegram,VIP,нет
```

- Разделитель — запятая или точка с запятой.
- В столбце `paid` значение «да» (также `yes`, `true`, `1`, `y`) считается оплатой, всё остальное — неоплатой.
- Пустые город или канал попадают в строку «(не указан)».

## Структура репозитория

| Путь | Назначение |
| --- | --- |
| `public/index.html` | Дашборд: одна самодостаточная страница. Это единственное, что публикуется на сайте |
| `registrations.csv` | Исходные данные (30 регистраций) |
| `scripts/update_data.py` | Переносит данные из CSV в страницу без имён (`update.bat` запускает его двойным кликом) |
| `old/` | Более ранняя версия дашборда с графиками и фильтрами |

## Деплой на Cloudflare Pages

Сайт публикуется из папки `public/`, сборка не нужна.

1. В [dash.cloudflare.com](https://dash.cloudflare.com) откройте **Workers & Pages → Create → Pages → Connect to Git** и выберите этот репозиторий.
2. Настройки сборки: **Framework preset** — `None`, **Build command** — пусто, **Build output directory** — `public`.
3. Нажмите **Save and Deploy**. Дальше каждый `git push` в `main` обновляет сайт автоматически.

## Данные на сайте

В опубликованную страницу вшиты только четыре столбца: `city`, `registered`, `source`, `paid`. Имена участников на сайт не попадают. Новую выгрузку на сайте можно посмотреть кнопкой «Загрузить другой CSV»: файл остаётся в вашем браузере.

### Как обновить вшитые данные

Нужен Python 3. Положите новую выгрузку в `registrations.csv` (или укажите другой файл) и запустите скрипт:

```bash
python scripts/update_data.py            # берёт registrations.csv
python scripts/update_data.py путь/к/выгрузке.csv
python scripts/update_data.py --check    # только проверить, совпадает ли страница с CSV
```

На Windows можно запустить двойным кликом `scripts/update.bat`.

Скрипт:

- сам определяет кодировку (UTF-8, Windows-1251, UTF-16) и разделитель (`,` `;` или табуляция);
- понимает русские заголовки (`город`, `канал`, `оплата`, `дата регистрации`) и даты `ДД.ММ.ГГГГ`;
- оставляет в странице только `city`, `registered`, `source`, `paid`, имена и остальные столбцы не попадают;
- приводит `да/yes/true/1` к «да», а `нет/no/false/0` к «нет»; нераспознанные значения оставляет как есть и предупреждает;
- пропускает строки «Итого/Всего» и сообщает о повторах, пустых городах и каналах, нераспознанных датах;
- печатает число регистраций, оплативших и дату последней регистрации: сверьте их с ожидаемыми и только потом делайте `git commit` и `git push`.

Вшитые данные не обновляются сами: под заголовком страницы показана дата последней регистрации.

## Защита от неверных цифр

При загрузке CSV страница проверяет файл и показывает предупреждения:

- **Кодировка:** файл читается как UTF-8, а если это не он (например, «CSV» из Excel в Windows-1251) — как Windows-1251. Под заголовком об этом сообщается.
- **Оплата:** распознаются «да» и «нет» (а также `yes/no`, `true/false`, `1/0`, «оплачено»). Остальные значения считаются как «не оплатили», и страница говорит, сколько их и какие.
- **Итоговые строки** «Итого/Всего» пропускаются и не считаются регистрациями.
- **Похожие написания** (`Telegram` и `telegram`), **повторяющиеся участники** (имя и город), **пустые город или канал** — выводятся в предупреждении, но данные не меняются.

## Персональные данные

`registrations.csv` и `old/data.js` содержат имена участников. Если репозиторий публичный, они видны на GitHub и в истории коммитов.

## Аудит

Критический разбор проекта на 21.11.2026. Общая оценка: годится как инструмент на один раз (7/10), но не как постоянно работающий сервис (4/10).

### Что проверено и верно

- На текущих данных: 30 регистраций, 20 оплатили, 10 не оплатили. Суммы по каналам и городам пересчитаны отдельно от кода дашборда и совпали.
- Вшитые данные в `public/index.html` построчно совпадают с `registrations.csv` по столбцам `city`, `registered`, `source`, `paid`. Это можно проверить командой `python scripts/update_data.py --check`.
- Вывод на страницу идёт через `textContent`, поэтому содержимое CSV не может внедрить в страницу код.

### Что уже исправлено

| Было | Стало |
| --- | --- |
| Файл Excel в Windows-1251 давал «0 оплативших» без ошибки | Кодировка определяется автоматически, на странице есть пометка |
| Неизвестные значения в `paid` молча считались неоплатой | Жёлтая плашка с количеством и примерами значений |
| Строка «Итого» считалась регистрацией | Строки «Итого/Всего» пропускаются |
| Не было видно, на какую дату данные | Под заголовком показана дата последней регистрации |
| Данные в страницу переносились вручную | Скрипт `scripts/update_data.py` делает это сам и не пропускает имена |

### Открытые риски

**Высокий приоритет**

- **Имена участников в публичном репозитории.** Они лежат в `registrations.csv`, `old/data.js`, в примерах `README.md` и в истории git. Сайт без имён не защищает репозиторий. Решение: сделать репозиторий приватным (Cloudflare Pages умеет с ним работать), убрать `old/data.js` и имена из примеров, а при необходимости почистить историю.

**Средний приоритет**

- **Нет автоматических тестов.** Парсер CSV и скрипт обновления проверялись вручную.
- **Устаревание данных.** Страница показывает дату последней регистрации, но не предупреждает, что она старая.
- **Русские заголовки и даты `ДД.ММ.ГГГГ` не понимает сама страница** при загрузке файла кнопкой (скрипт обновления их понимает). Выгрузка со столбцами «Город / Канал / Оплата» даст ошибку, а формат даты Excel не распознается без предупреждения. Табуляция в качестве разделителя тоже не поддерживается.
- **Строки итогов** пропускаются только при точном совпадении («Итого», «Всего», «Total»). «Итого по Астане» посчитается как регистрация.

**Низкий приоритет**

- **Разные написания** (`Telegram` и `Телеграм`) не склеиваются, страница только предупреждает о различии регистра.
- **Проверка повторов** по имени и городу не работает на вшитых данных, потому что имён там нет.
- **Проценты на малых группах** вводят в заблуждение: 2 человека из 2 дают «100%».
- **Ошибка загрузки** заменяет предупреждения, относящиеся к ранее показанным данным.
- **Папка `old/`** дублирует данные с именами и не нужна для публикации.

### Ограничения самого показателя

- «Оплатил» означает пометку «да» в файле, а не поступившие деньги. Возвраты и рассрочка не учитываются.
- Выручка, разрез по типам билетов (`ticket`) и динамика регистраций по дням не показываются, хотя данные для них в выгрузке есть.
- Нет сравнения с планом набора.

### Рекомендуемый порядок работ

1. Закрыть имена: приватный репозиторий, удаление `old/data.js` и имён из README.
2. Добавить предупреждение «данным больше 7 дней».
3. Научить страницу русским заголовкам, датам `ДД.ММ.ГГГГ` и табуляции.
4. Добавить динамику по дням и разрез по типу билета.
5. Положить в репозиторий тестовые CSV и автоматическую проверку парсера.
